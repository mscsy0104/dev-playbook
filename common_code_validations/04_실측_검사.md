# 04. 실측 검사

- 대상: 납품 전에 실제 외부 서비스 전체에 전체 처리를 실행해 결과를 확인하는 검사. 로컬 PC와 원격(납품) 서버에서 같은 항목을 본다.
- 언어 · 도구에 매이지 않게 썼다. Python 프로젝트의 명령은 맨 끝 "부록: Python 예"에 있다.

## 1. 실측 검사란

- 가짜 응답이 아니라 실제 외부 서비스에서 목록을 받고 항목을 내려받는다.
- 단위 테스트가 통과해도 외부 서비스가 바뀌었으면(목록 구조, 로그인 화면, 파일 이름 규칙) 실측에서만 드러난다.
- 원격 서버에서 다시 하는 이유: 서버 네트워크(사내망 · 외부 접속 허용 목록), 디스크, 컨테이너 권한은 로컬 PC와 다르다.

## 2. 확인 항목과 통과 기준

| # | 항목 | 보는 곳 | 통과 | 실패(확인 필요) |
|---|---|---|---|---|
| 1 | 작업 상태 | 작업 기록의 상태 | 성공 | 실패(작업 오류 코드 확인), 부분 성공(실패 행 있음) |
| 2 | 목록 건수 | 작업 기록의 목록 건수 | 이전 실행과 비슷함(기준값 표) | 크게 줄거나 늘어남. 목록 축소 기준 비율 이상 줄면 작업 실패 |
| 3 | 항목 결과 | 결과 행 파일의 결과 열 | 모두 성공 | 실패 행: 오류 코드 확인 |
| 4 | 목록 항목 검증 실패 | 결과 행의 비고, 로그 `응답 구조 검증 실패` 같은 경고 | 0건 | 1건 이상: 외부 응답 구조가 바뀜 |
| 5 | 부분 값(날짜 등) | 결과 행의 해당 열, 부분 값 읽기 실패 경고 | 기준값 표와 비슷함, 경고는 기준값 표에 적은 것만 | 새 경고: 원본의 값 형식이 바뀜 |
| 6 | 로그인 | 로그인 실패 오류 코드(인증이 있는 외부 서비스) | 없음 | 있음: 다시 시도하지 않고 자격증명 확인 |
| 7 | ERROR 로그 | 대상별 ERROR 로그 파일 | 파일 없음 | 내용 확인 |
| 8 | 파일 | 성공 행의 저장 파일 | 파일이 있고 크기 = 결과 행의 크기, 앞 바이트가 기대한 형식 시그니처 | 파일 없음 · 크기 다름 |

- 결과 행의 해시가 저장 파일 바이트의 해시가 아닌 행(예: 렌더링 전 원본의 해시를 쓰는 행)이 있으면 그 이유와 함께 적는다. 이유: 그 행의 파일 해시가 결과 행과 다른 것을 정상으로 판단할 수 있어야 한다.

### 기준값

실행할 때마다 다음 표를 채우고 실행 날짜 · 환경(로컬 · 원격, 동시 실행 여부)을 적는다.

| 대상 | 목록 건수 | 이전 실행(날짜) | 소요 | 부분 값 있는 건수 | 경고 |
|---|---|---|---|---|---|

- 모든 대상의 상태, 모든 행의 결과, 목록 항목 검증 실패 건수, ERROR 건수를 한 줄로 적는다.
- 부분 값이 빈 행은 이유를 적는다(로그 없이 빈칸이면 원본에 값을 적는 자리가 원래 없는 경우).
- 결과 기록 위치: `<실행 기록 폴더>/<날짜>_<티켓>_<대상>/`.

## 3. 로컬

### 3-0. 실측 전에 외부 연동 테스트

전체 처리 전에 외부 서비스마다 목록 조회와 항목 하나만 받아 보는 외부 연동 테스트를 먼저 실행한다. 외부 서비스가 바뀌었으면 몇 분 안에 알 수 있다.

- 자격증명은 메인 저장소 루트의 `.env`에서 읽는다(worktree에서 실행해도 같다). 셸에 같은 이름의 환경변수가 있으면 그 값이 우선한다.
- 자격증명 환경변수가 없거나 비어 있는 대상은 skip하고, 사유에 빠진 환경변수 이름을 쓴다.
- 실패하면 메시지가 `[단계] 오류 코드 상세`로 시작하게 한다. 단계: 로그인 · 목록 · 목록 항목 · 파일 · 파일 내용. 실패한 대상은 실측 전에 원인을 확인한다.

### 3-1. 준비

- 결과 폴더 `<실행 기록 폴더>/<날짜>_<티켓>_<대상>/`를 만들고 쓸 설정 파일을 복사해 둔다.
- 인증이 있는 외부 서비스는 작업 하나에 로그인 1회로 한다. 로그인 실패가 나면 다시 실행하지 않는다. 이유: 여러 번 실패하면 계정이 잠길 수 있다.
- 비밀번호 값을 화면 · 로그에 출력하지 않는다(로그는 마스킹됨).

### 3-2. 서버 실행

- 저장 루트와 설정 파일 경로를 환경변수로 주고, `.env`의 자격증명을 환경변수로 넣어 서버를 실행한다. 서버 로그는 결과 폴더의 파일로 받는다.
- 헬스 체크가 정상인지 확인한다.
- 대상마다 포트와 저장 루트를 다르게 해 서버를 따로 실행하면 동시에 처리하고 결과 폴더도 대상별로 나뉜다.

### 3-3. 처리 · 결과 확인

1. 전체 처리를 접수하고 응답을 결과 폴더에 저장한다.
2. 작업 상태가 실행 중이 아닐 때까지 일정 간격으로 조회한다.
3. 결과 행 파일을 요약한다: 행 수와 결과별 건수, 비고별 건수, 오류 코드별 건수, 부분 값 있는 건수(확인 항목 3 · 4 · 5).
4. 서버 로그에서 경고 · 오류 건수를 센다: 응답 구조 검증 실패, 부분 값 읽기 실패, ERROR, 로그인 실패, ERROR 로그 폴더(확인 항목 4 · 5 · 6 · 7).

### 3-4. 파일 확인 · 삭제 · 서버 종료

1. 성공 행마다 저장 파일이 있는지, 크기가 결과 행과 같은지, 앞 바이트가 형식 시그니처인지 확인한다(확인 항목 8).
2. 확인 뒤 큰 파일(PDF · ZIP 등)을 지운다. 이유: 전체 처리 한 번이 12GB를 남긴 적이 있다.
3. 서버 프로세스에 종료 신호(SIGTERM)를 보내고, 프로세스가 없어졌는지 확인한다.

- 남기는 것: 결과 행 파일, 작업 기록, 서버 로그, 설정 파일, 상태 파일.

## 4. 원격(납품 서버, 사용자가 실행)

- 서버 셸에서 실행한다. 컨테이너 안에 HTTP 클라이언트가 없을 수 있다.
- 데이터 폴더 소유자가 컨테이너 사용자 UID이면, 권한 오류가 날 때 관리자 권한을 붙인다.

### 4-1. 준비 · 기동

1. 설정 파일에 이미 없앤 키가 남아 있지 않은지 확인한다. 남아 있으면 기동이 실패한다(설정 오류).
2. 컨테이너를 다시 만들어 기동하고, 상태가 healthy인지 확인한다.
3. 헬스 체크가 200인지 확인한다.

### 4-2. 처리

- 모든 대상을 한 번에 접수하면 동시에 실행된다. 동시 실행 상한이 대상 수 이상이어야 거부되지 않는다.

### 4-3. 상태 확인

- 대상마다 작업을 조회해 상태 · 목록 건수 · 오류 코드를 출력한다. 모두 실행 중이 아닐 때까지 몇 분마다 다시 실행한다. 가장 긴 대상의 로컬 소요 시간을 기준으로 기다린다.

### 4-4. 결과 확인

- 대상마다 결과 행 파일을 결과 폴더로 복사하고 로컬과 같은 요약을 출력한다.
- 컨테이너 로그를 파일로 받아 경고 · ERROR 건수를 센다. ERROR 로그 폴더를 확인한다.
- 통과 기준은 확인 항목 표와 같다. 건수는 기준값 표와 비교한다(외부 서비스가 항목을 더하거나 빼면 몇 건 달라질 수 있다).

### 4-5. 마친 뒤

- 결과 폴더의 디스크 사용량을 기록한다.
- 작업 기록, 결과 행 파일, 컨테이너 로그를 결과로 보관한다.

## 부록: Python 예

uvicorn · FastAPI 서비스, 결과 행 파일이 CSV인 경우다.

```bash
# 3-0 외부 연동 테스트
uv run pytest tests/live               # 모든 대상
uv run pytest tests/live -k "a or b"   # 인증 없는 대상만
uv run pytest tests/live -s            # 목록 건수 · 항목 키 · 받은 바이트 수도 출력

# 3-1 준비
W=<worktree 또는 저장소 루트>
ENV=<repo>/.env
D=<repo>/<실행 기록 폴더>/$(date +%F)_<티켓>_<대상>
mkdir -p $D/data && cp $W/<설정 파일> $D/

# 3-2 서버 실행
cd $W
ROOT=$D/data SITES_CONFIG=$D/<설정 파일> \
  uv run --env-file $ENV uvicorn --factory pkg.main:app_factory \
  --host 127.0.0.1 --port 8041 --workers 1 --no-access-log > $D/server.log 2>&1 &
curl -s http://127.0.0.1:8041/health

# 3-3 접수 · 대기
curl -s -X POST http://127.0.0.1:8041/collect -H 'Content-Type: application/json' \
  -d '{"target":"<대상>","mode":"full"}' | tee $D/post_full.json
ID=$(python3 -c "import json;print(json.load(open('$D/post_full.json'))['execution_id'])")
until [ "$(curl -s http://127.0.0.1:8041/executions/$ID | python3 -c 'import json,sys;print(json.load(sys.stdin)["status"])')" != running ]; do sleep 60; done

# 3-3 결과 행 요약
python3 - $D/data/results/*/$ID/<결과 행 파일>.csv <<'EOF'
import csv, collections, sys
r = list(csv.DictReader(open(sys.argv[1], encoding="utf-8")))
print("rows", len(r), collections.Counter(x["result"] for x in r))
print("remark", collections.Counter(x["remark"] for x in r))
print("err_code", collections.Counter(x["err_code"] for x in r if x["err_code"]))
EOF
grep -c '"level": "ERROR"' $D/server.log

# 3-4 파일 확인
python3 - $D/data/results/*/$ID/<결과 행 파일>.csv <<'EOF'
import csv, os, sys
f = sys.argv[1]; d = os.path.dirname(f); bad = 0
for x in csv.DictReader(open(f, encoding="utf-8")):
    if x["result"] != "success":
        continue
    p = os.path.join(d, x["stored_file"])
    head = open(p, "rb").read(4) if os.path.exists(p) else b""
    if not os.path.exists(p) or os.path.getsize(p) != int(x["size"]) or head not in (b"%PDF", b"PK\x03\x04"):
        bad += 1; print("bad", x["key"])
print("bad", bad)
EOF

# 3-4 삭제 · 종료
find $D/data/results -type f \( -name '*.pdf' -o -name '*.zip' \) -delete
pkill -TERM -f 'uvicorn.*--port 8041'
pgrep -fl 'port 8041' || echo stopped
```

```bash
# 4 원격(docker compose)
export ADDR=127.0.0.1:8000
export SVC_HOME=<docker-compose.yaml이 있는 폴더>
export OUT=$HOME/live_out; mkdir -p "$OUT"
cd "$SVC_HOME"
docker compose up -d --force-recreate
docker compose ps                         # STATUS에 (healthy)
curl -s -w '\nHTTP %{http_code}\n' http://$ADDR/health
docker compose logs --no-log-prefix <서비스> > "$OUT/stdout_full.log"
du -sh "$SVC_HOME"/data/results/*
```
