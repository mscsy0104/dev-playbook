# 01. 단위 테스트

- 대상: 로컬 PC에서 테스트 러너로 실행하는 테스트(`tests/` 폴더). 기본 실행은 단위(`tests/unit`)와 통합(`tests/integration`)
- 언어 · 도구에 매이지 않게 썼다. Python 프로젝트의 설정 · 명령 · 출력은 맨 끝 "부록: Python 예"에 있다.

## 1. 무엇을 확인하는가

- 함수 · 모듈 하나가 정해진 입력에 정해진 결과를 반환하는지, 실패할 때 정해진 오류 코드로 실패하는지 확인한다.
- 실제 외부 서비스에 접속하지 않는다. 외부 응답은 테스트 안에 적은 값이나 HTTP 클라이언트의 가짜 전송 계층으로 만든 응답을 쓴다.
  - 이유: 외부 서비스 상태와 관계없이 짧은 시간 안에 같은 결과가 나와야 커밋 전마다 실행할 수 있다.
- 층은 폴더로 나눈다.
  - 단위 `tests/unit/`: 함수 · 모듈 하나.
  - 통합 `tests/integration/`: 범위가 넓은 테스트. 처리 전체 흐름(e2e: API 요청 → 실행 엔진 → 가짜 외부 응답 → 결과 파일 · 작업 기록 · 상태 파일), 웹 프레임워크 앱의 HTTP 요청 · 응답, 실제 브라우저 실행, 실제 하위 프로세스 실행.
  - 외부 연동 `tests/live/`: 실제 외부 서비스에 접속한다. 기본 실행에 들어가지 않고 경로를 지정할 때만 실행된다.

## 2. 설정과 도구

| 항목 | 정할 것 | 위치 |
|---|---|---|
| 실행 도구 | 테스트 러너와 버전 | 잠금 파일 |
| 비동기 테스트 | 비동기 테스트 플러그인과 표시 방법 | 프로젝트 설정 파일 개발 의존성 |
| 브라우저 테스트 | 브라우저 자동화 플러그인과 브라우저 | 프로젝트 설정 파일 개발 의존성 |
| import 경로 | 소스 폴더를 import 경로에 넣기 | 프로젝트 설정 파일 테스트 절 |
| 수집 범위 | 기본 실행은 단위 · 통합만. 외부 연동 · 스모크는 경로를 지정할 때만 | 프로젝트 설정 파일 테스트 절 |

- 처음 한 번 의존성을 설치해 가상 환경을 만든다. 실행 명령이 실행 전에 가상 환경을 잠금 파일에 맞추게 한다.
- 실제 브라우저를 실행하는 테스트 파일은 그 파일 하나로 모은다(다른 파일은 가짜 브라우저 객체를 쓴다). 브라우저가 없으면 설치 명령을 한 번 실행한다.

## 3. 폴더 구성

```
tests/
├── <공통 fixture 파일>     # 모든 테스트: 설정 환경변수 지우기(자동 적용)
├── <결과 행 검사 도우미>
├── <상태 파일 읽기 도우미>
├── <결과 파일 검사 도우미>
├── <외부 연동 판단 도우미>  # 외부 접속 없음
├── unit/
│   ├── <공통 fixture 파일> # fixture: 임시 폴더 저장소, 경고 로그 수집
│   └── <테스트 파일들>
├── integration/
│   └── <테스트 파일들>
└── live/
    ├── <공통 fixture 파일> # 외부 연동: 대상 설정 · 자격증명 fixture
    └── <테스트 파일>        # 외부 서비스 목록으로 매개변수화
```

- 여러 층이 함께 쓰는 도우미는 `tests/` 바로 아래에 둔다. 이유: 테스트 러너가 `tests/`를 import 경로에 넣으면 모든 층에서 같은 이름으로 import된다.
- 공통 fixture: 설정 객체가 읽는 환경변수(저장 루트, 설정 파일 경로, 로그 레벨 등)를 테스트마다 지운다.
  - 이유: 개발자 셸에 같은 이름의 값이 있어도 테스트 결과가 바뀌지 않게.
  - 테스트 안에서 설정이 필요하면 그 테스트에서 환경변수를 다시 넣는다.
- 단위 층 fixture
  - 저장소: 테스트마다 새 임시 폴더를 저장 루트로 쓰는 구체 저장소 구현.
  - 경고 로그 수집: 로그 수집기에 로그 문맥 필터를 붙여 문맥 필드(항목 키 · 작업 id 등)까지 확인할 수 있게 한다. WARNING 이상만 모은다.

## 4. 무엇이 테스트되는가

테스트 러너의 "수집만 하고 실행하지 않음" 기능으로 건수를 세고, 기준 커밋 · 날짜와 함께 적는다. 기본 실행 건수 = 단위 + 통합. 외부 연동 · 스모크 건수는 따로 적는다.

단위 표의 열: 대상 모듈 · 테스트 파일 · 건수 · 확인하는 것. 건수가 많은 모듈부터 적고, 나머지는 "그 밖"으로 묶는다. 확인하는 것의 예:

| 대상 | 확인하는 것 |
|---|---|
| 오류 정의 | 오류 코드 → 분류 · 메시지 표, 오류 메시지 만들기 |
| 외부 연동 모듈 · 응답 모델 | 목록 · 첨부 읽기, 응답 모델 검증, 날짜 읽기 |
| 마스킹 | 로그 안 비밀번호 · 토큰 마스킹 |
| HTTP 공통 | HTTP 오류 → 오류 코드 변환, 재시도, 속도 제한 |
| 실행 엔진 | 작업 실행, 체크포인트, 중단 · 시간 초과, 목록 항목 검증 실패 행, 마지막 작업 기록 쓰기 실패 · 종결 때 파일 삭제 실패 |
| 업무 계층(접수) | 접수 · 거부 사유 코드, 작업 기록 · 상태 파일 엄격 읽기, 기동 때 마치지 못한 작업 WARNING |
| 저장소 | 원자적 쓰기(임시 파일 → 이름 바꾸기) |
| 설정 파일 | 모르는 키 거부, 중복 키, 값 사이 규칙 |
| 설정 객체 | 환경변수 형식 · 범위 검사 |
| 로깅 | 구조화 로그, 대상별 ERROR 로그 파일 |
| 계층 규칙 | import 순환 없음, 모듈 하나씩 import 가능, import 규칙 계약 통과 |

통합 표의 열: 테스트 파일 · 건수 · 확인하는 것. 확인하는 것의 예:

| 테스트 | 확인하는 것 |
|---|---|
| API | HTTP 상태 · 응답 본문 `{code, message, detail}`, 기동 검사(구현 없는 대상 기동 실패, 자격증명 · 마치지 못한 작업 WARNING), 타입이 틀린 작업 기록 · 상태 파일의 거부 |
| 처리 e2e(외부 서비스마다) | 처리 요청 → 결과 파일(결과 행 · 작업 기록 · 상태). 성공한 전체 처리 끝에 결과 파일 검사 도우미로 파일 · 크기 · 해시 · 상태를 확인 |
| 실제 브라우저 | HTML → PDF 등 실제 브라우저 동작 |
| 강제 종료 | 쓰는 도중 하위 프로세스를 강제 종료해도 반쯤 쓰인 파일이 없음 |

## 5. 명령

모두 worktree(또는 저장소) 루트에서 실행한다. 테스트 러너마다 다음 실행 방법을 확인해 두고, 명령은 부록에 적는다.

| 실행 | 쓰는 때 |
|---|---|
| 기본 실행(단위 + 통합) | 커밋 전 |
| 층 하나 | 층별 시간을 잴 때 |
| 결과 줄만 짧게 | 건수만 볼 때 |
| 파일 하나 · 함수 하나 | 고치는 모듈을 확인할 때 |
| 이름에 낱말이 들어간 테스트만 | 관련 테스트만 골라 볼 때 |
| 첫 실패에서 멈추고 자세한 출력 | 실패 원인을 볼 때 |
| 직전에 실패한 테스트만 | 고친 뒤 다시 확인할 때 |
| 수집만 하고 실행하지 않음 | 목록 · 건수 확인 |

## 6. 결과 읽기

- 진행 표시에서 통과 · 실패 · 준비 단계 오류 · 건너뜀을 구분한다.
- 마지막 줄에 통과 · 실패 · 건너뜀 건수와 걸린 시간이 나온다.
- 경고 요약은 실패가 아닌 경고다.
- 실패하면 실패한 테스트 이름, 실패한 단언 줄, 기대값 · 실제값을 본다.
- 모듈을 찾지 못하는 오류가 나면 가상 환경이 다른 폴더의 소스를 가리키는 경우다. 활성화된 가상 환경 변수를 지우고 의존성을 다시 설치한 뒤 실행한다.

## 7. 언제 실행하는가

- 커밋 전마다 기본 실행과 import 규칙 검사, 린터, 정적 타입 검사, 포매터 검사(포매터를 쓰는 프로젝트)를 실행한다.
  - 이유: 전체가 1분 안쪽이면 일부만 고를 이유가 없다.
- 코드를 고치는 중에는 고친 모듈의 테스트 파일만 실행하고, 끝나면 전체를 실행한다.

## 부록: Python 예

| 항목 | 값 |
|---|---|
| 테스트 러너 | pytest(`uv.lock`) |
| 비동기 테스트 | pytest-asyncio. 파일마다 `pytestmark = pytest.mark.asyncio` |
| 브라우저 테스트 | pytest-playwright, Chromium. 설치 `uv run playwright install chromium` |
| 가짜 HTTP 응답 | `httpx.MockTransport` |
| 웹 프레임워크 | FastAPI |
| import 경로 | `pyproject.toml` `[tool.pytest.ini_options]` `pythonpath = ["src"]` |
| 수집 범위 | `testpaths = ["tests/unit", "tests/integration"]` |
| 공통 fixture 파일 | `tests/conftest.py`(autouse), `tests/unit/conftest.py`, `tests/live/conftest.py` |
| 테스트 안 환경변수 | `monkeypatch.setenv` |
| 경고 로그 수집 | `caplog`에 로그 문맥 필터를 붙인 fixture |
| 의존성 설치 | `uv sync`(`uv run`은 실행 전에 `.venv`를 `uv.lock`에 맞춤) |

```bash
uv run pytest                                   # 기본 실행: 단위 + 통합
uv run pytest tests/unit                        # 층 하나
uv run pytest tests/integration
uv run pytest -q                                # 결과 줄만 짧게
uv run pytest tests/unit/test_doc_dates.py      # 파일 하나
uv run pytest tests/unit/test_doc_dates.py::test_parse_yyyymm   # 함수 하나
uv run pytest tests/unit/test_manager.py -k concurrency         # 이름에 낱말
uv run pytest -x -vv                            # 첫 실패에서 멈춤, 자세한 출력
uv run pytest --lf                              # 직전 실패만
uv run pytest --collect-only -q                 # 수집만
```

- 진행 줄: 점(`.`) 통과, `F` 실패, `E` fixture 단계 오류, `s` 건너뜀.
- 경고 요약: `warnings summary`. 실패 상세: `FAILURES` 절, 목록: `short test summary info`.

  ```
  FAILED tests/unit/test_doc_dates.py::test_parse_yyyymm[jan2024-2024-01] - AssertionError: assert '2024-02' == '2024-01'
  ```

- 모듈을 찾지 못하는 오류: `ModuleNotFoundError: <패키지>` → `env -u VIRTUAL_ENV uv sync` 뒤 다시 실행.
