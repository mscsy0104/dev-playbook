# 05. 스모크 검사

- 대상: 새로 만든 컨테이너 이미지가 기본 기능을 하는지 짧게 확인하는 검사
- 언어 · 도구에 매이지 않게 썼다. Python · Docker 프로젝트의 명령은 맨 끝 "부록: Python 예"에 있다.

## 1. 스모크 검사란

- 새로 만든 결과물을 켜 보고 핵심 기능 몇 개만 실제로 실행해, 크게 고장 난 곳이 없는지 확인하는 짧은 검사다.
  - 이름은 하드웨어를 처음 켰을 때 연기(smoke)가 나지 않는지 보는 데서 왔다.
- 모든 기능을 확인하지 않는다. "켜지는가, 한 번 처리되는가, 결과 파일이 맞는가"만 본다. 10분 안에 끝나게 대상을 고른다.
- **이미지를 새로 만들 때마다, 서버에 올리기 전에** 로컬에서 한 번 실행한다.

## 2. 왜 납품 전에 필요한가

단위 테스트 · 정적 검사가 모두 통과해도 이미지에서만 생기는 문제가 있다. 이 문제는 스모크 검사로만 드러난다.

| 이미지에서만 생기는 문제 | 단위 테스트에서 보이지 않는 이유 | 스모크 검사에서 보이는 모습 |
|---|---|---|
| 운영 의존성 목록에 패키지가 빠짐 | 로컬 가상 환경은 잠금 파일 전체(개발 의존성 포함)를 설치함 | 기동 실패(모듈을 찾지 못함) |
| 브라우저 · 글꼴이 이미지에 없음 | 로컬 PC에는 설치돼 있음 | 브라우저를 쓰는 로그인 · 렌더링 실패 |
| 데이터 폴더 권한(컨테이너 사용자 UID) | 테스트는 임시 폴더를 씀 | 헬스 체크 503 저장소 사용 불가 |
| 설정 파일 마운트 경로 · 설정 파일 경로 환경변수 | 테스트는 설정 객체를 직접 만듦 | 기동 실패(설정 오류, 파일 읽기 실패) |
| 이미지 실행 명령 · 포트 | 테스트는 앱을 직접 만듦 | 헬스 체크에 응답 없음 |

## 3. 다른 검사와 다른 점

| 검사 | 무엇을 실행하나 | 외부 서비스 접속 | 시간 |
|---|---|---|---|
| 단위 · 통합 테스트 | 소스 코드의 함수 · API부터 결과 파일까지 | 안 함(가짜 응답) | 짧음(실측) |
| 정적 검사 | 실행하지 않음(코드만 읽음) | 안 함 | 수 초 |
| 런타임 검사 | 서비스 안의 검사 코드 | 운영 중에 늘 | 늘 |
| **스모크 검사** | **완성된 컨테이너 이미지** | **대상 하나, 인증 없는 대상** | **몇 분** |
| 실측 검사 | 소스 또는 이미지, 모든 대상 전체 | 모든 대상 | 대상마다 몇 분~수십 분 |

- 스모크 검사는 실측 검사의 가장 작은 판이다. 스모크가 실패하면 실측 검사를 시작하지 않는다.
- 인증 없는 대상을 쓰는 이유: 자격증명(`.env`)이 필요 없고, 잘못 시도해 계정이 잠길 위험이 없다.

## 4. 최소 확인 목록

| # | 확인 | 통과 기준 |
|---|---|---|
| 1 | 이미지 빌드 | 빌드 종료 코드 0 |
| 2 | 기동 | 로그에 기동 처리 완료 문구(임시 파일 삭제 건수 등)와 웹 서버 기동 완료 문구 |
| 3 | 저장소 쓰기 | 헬스 체크 200 |
| 4 | 처리 접수 | 처리 요청 → 202, 상태 실행 중 |
| 5 | 처리 완료 | 작업 조회 → 상태 성공, 목록 건수가 이전 실행과 비슷함(기준값을 날짜와 함께 적는다) |
| 6 | 결과 파일 | 결과 행 수 = 목록 건수, 결과가 모두 성공, 파일 하나가 실제 기대한 형식 |
| 7 | 오류 로그 | 로그에 ERROR 없음, 대상별 ERROR 로그 파일 없음 |
| 8 | 컨테이너 삭제 | 컨테이너 중지 · 삭제 |

## 5. 실행

### 5-1. 테스트로 실행

최소 확인 목록을 스모크 테스트 하나가 순서대로 실행하게 만든다.

- 기본 테스트 실행에는 들어가지 않는다. 경로를 지정할 때만 실행된다.
- 대상은 환경변수로 바꿀 수 있게 하고 기본값을 정한다.
- 기동 로그 문구 대신 헬스 체크를 정한 시간 안에 기다린다. 결과 파일은 결과 파일 검사 도우미로 성공 행 전부의 파일 · 크기 · 해시 · 형식과 상태 파일을 확인한다. 오류 로그는 컨테이너 로그에 ERROR 레벨이 없고 대상별 ERROR 로그 파일이 없는지 본다.
- 실패하면 실패한 단계가 메시지 앞에 붙는다: `[이미지 빌드]` · `[기동]` · `[처리 접수]` · `[처리 완료]` · `[결과 파일]` · `[오류 로그]`. 처리 완료 대기와 빌드에 시간 상한을 둔다.
- 컨테이너 실행 도구가 없으면 `[이미지 빌드]` 단계 실패로 끝낸다(skip하지 않음). 이유: 경로를 지정할 때만 실행되는 테스트라 skip하면 실행되지 않은 검사가 통과로 보인다.
- 끝나면 성공 · 실패와 관계없이 컨테이너를 중지 · 삭제하고 임시 폴더를 지운다. 그 전에 컨테이너 로그(`server.log`)와 작업의 결과 행 파일 · 작업 기록 · 상태 파일을 메인 저장소 `<실행 기록 폴더>/<YYYY-MM-DD>_smoke_<대상>/`에 복사한다(큰 결과 파일은 복사하지 않음).

### 5-2. 손으로 실행

같은 순서를 명령으로 실행한다. 저장소 루트(또는 worktree)에서 실행한다.

1. 이미지를 빌드한다.
2. 임시 데이터 폴더를 compose와 같은 마운트 구성으로 만든다.
3. 컨테이너를 실행한다(데이터 폴더와 설정 파일을 마운트, 포트는 로컬에만 연다).
4. 헬스 체크.
5. 대상 하나의 전체 처리를 접수한다.
6. 끝날 때까지 일정 간격으로 작업을 조회한다.
7. 결과 행 수와 결과별 건수, 파일 하나의 형식, 컨테이너 로그 ERROR 건수, ERROR 로그 폴더를 확인한다.
8. 컨테이너를 중지 · 삭제하고 임시 폴더를 지운다.

## 6. 결과 기록

실행할 때마다 다음을 적는다(실제 실행한 것만).

- 실행 날짜 · 실행자 · 커밋 또는 이미지, 대상, 통과 여부.
- 작업 id, 상태, 목록 건수, 시작 · 끝 시각(UTC)과 소요 시간.
- 결과 행 수와 결과별 건수, 결과 파일 검사 도우미 통과 여부.
- 컨테이너 로그의 ERROR · WARNING 건수와 WARNING마다 이유. 예: 컨테이너에 `.env`를 넘기지 않아 다른 대상의 자격증명이 없다는 기동 WARNING은 이번 처리와 관계없다. 다시 시도해 받은 HTTP 시간 초과 재시도 WARNING은 실패가 아니다.
- 기록 위치.

## 7. 실패하면

| 증상 | 먼저 볼 곳 |
|---|---|
| 기동 실패 · 컨테이너가 바로 종료 | 컨테이너 로그의 마지막 줄(설정 오류, 설정 검증 오류, 모듈을 찾지 못함) |
| 헬스 체크 503 | 마운트한 폴더 권한. 컨테이너 사용자 UID로 쓴다 |
| 작업 상태 실패 | 작업 기록의 오류 코드 · 오류 메시지. 예: 목록이 비었음(외부 목록 구조가 바뀜) |
| 실패 행 | 그 행의 오류 코드. 예: 파싱 실패는 받은 파일이 기대한 형식이 아님 |

## 부록: Python 예

Docker · uvicorn 이미지, 결과 파일이 PDF인 경우다.

```bash
# 5-1 테스트로 실행 (tests/smoke/test_image.py)
uv run pytest tests/smoke
SMOKE_TARGET=<대상> uv run pytest tests/smoke
```

- 기본 실행 제외: `pyproject.toml` `testpaths = ["tests/unit", "tests/integration"]`.
- 기동 완료 문구: uvicorn `Application startup complete.`
- 운영 의존성 목록: `requirements-prod.txt`(이미지에 설치), 잠금 파일 `uv.lock`.

```bash
# 5-2 손으로 실행
docker build -t <이미지>:smoke .

T=$(mktemp -d)
mkdir -p $T/results $T/states $T/logs

docker run -d --name svc-smoke --init -p 127.0.0.1:8050:8000 --shm-size 1g \
  -v $T/results:<컨테이너 데이터 경로>/results \
  -v $T/states:<컨테이너 데이터 경로>/states \
  -v $T/logs:<컨테이너 데이터 경로>/logs \
  -v $(pwd)/<설정 파일>:<컨테이너 데이터 경로>/<설정 파일>:ro \
  <이미지>:smoke

curl -s -w ' %{http_code}\n' http://127.0.0.1:8050/health
curl -s -w ' %{http_code}\n' -X POST http://127.0.0.1:8050/collect \
  -H 'Content-Type: application/json' -d '{"target":"<대상>","mode":"full"}'

ID=<execution_id>
until [ "$(curl -s http://127.0.0.1:8050/executions/$ID | python3 -c 'import json,sys;print(json.load(sys.stdin)["status"])')" != running ]; do sleep 15; done
curl -s http://127.0.0.1:8050/executions/$ID

R=$T/results/<대상>/$ID
python3 -c "import csv,collections,sys;r=list(csv.DictReader(open(sys.argv[1])));print(len(r),collections.Counter(x['result'] for x in r))" $R/<결과 행 파일>.csv
file "$(ls $R/*.pdf | head -1)"
docker logs svc-smoke 2>&1 | grep -c '"level": "ERROR"'
ls $T/logs

docker stop svc-smoke && docker rm svc-smoke
rm -rf $T
```

- 파일 형식 확인 출력 예: `... .pdf: PDF document, version 1.6, 2 pages`.
